# Data Bank (P-074) — 2026-11-07

Per-chat attached documents the model can read (the mirrors'
file-attachment memory), scoped and budgeted. Roadmap:
`docs/RUNMAL_TWO_MIRRORS_PARITY_ROADMAP_2026-10-30.md` P-074;
census kin ST-60 (per-chat/global attached documents).
Extension-registered **scrapers are not part of this slice**:
no scraper registry exists in Runmal yet, and none is claimed.

## What shipped

- `src/runmal/chats/databank.py` — the data bank. Documents are
  text (plain / markdown / CSV / JSON content types; binary is
  refused honestly), each with name, enabled flag, and priority.
- Two scopes: **chat** (attached to one chat, read only there)
  and **global** (attached to the owner, read by every chat of
  that owner — never another owner's).
- REST surface on the chats router: attach / list / get / update
  / detach under `/chats/{chat_id}/databank`, a declared budget
  under `/chats/{chat_id}/databank/budget`, and the global bank
  under `/databank/global`. Error mapping follows the checkpoint
  routes: missing chat/document 404, malformed or corrupt 422.
- Prompt integration: `inspect_prompt` with a `chat_id` adds the
  selected documents as `databank` slots and returns a
  `databank` accounting echo; excluded documents surface in the
  trace as discards with reasons.

## Storage — no migration

Documents ride the proven P-067 checkpoint pattern: one
self-contained JSON file per document under
`data_dir()/databank/<user_id>/<chat_id or _global>/`, sealed
with a SHA-256 checksum over the canonical document bytes,
written atomically (tmp sibling, chmod 0600, replace). The
per-chat budget lives in a likewise-sealed `_settings.json`.
Listing is a directory scan. Migration head stays **0038**.
Chat deletion removes the chat's bank directory (beside the
checkpoint cleanup); global documents survive — they belong to
the owner, not the chat.

Integrity: a document id is validated before any path is built
from it; a tampered file, a forged checksum, or a document filed
under the wrong scope raises `DataBankError` (422 at the API)
and is never confused with a missing document (404). Chat-scope
operations verify the owned chat before any file is touched.
Attach/update/detach/budget changes record chat events carrying
metadata only (ids, names, counts — never content).

## The budget contract

- Default budget **2000 tokens** per chat; declared per chat,
  range 0..100000 (0 excludes everything).
- One counter: `runmal.tokens` over the **rendered** document
  text (`[Data bank: <name>]` + content) — the exact text the
  prompt slot carries — so accounting equals slot spend; a
  caller-supplied counter is labelled EXACT.
- Selection is greedy in declared order (higher priority first,
  chat scope before global, then attach order) and includes
  **whole documents only**. A document that does not fit is
  excluded whole with reason `over_databank_budget`; a disabled
  one with `disabled`. Nothing is ever truncated to fit.
- Spend visibility: the accounting echo (`budget_tokens`,
  `spent_tokens`, `remaining_tokens`, included/excluded with
  per-document token counts and reasons) rides the list endpoint
  and the prompt-inspect result; in the whole-prompt budget the
  P-058 governor counts `databank` slots under its `context`
  section, and the composer still enforces the total input
  budget on top.
- Router boundary uses strict int/bool types: a JSON `true` is
  never coerced into a priority or budget of 1.
